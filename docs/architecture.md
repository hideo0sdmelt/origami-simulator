# 仕組み

コードを読む・直すときのための説明。機能の動きは [spec.md](spec.md) を参照。

## ファイル構成

| ファイル | 中身 |
|---|---|
| `index.html` | アプリの全部(HTML・CSS・JS を1ファイルに入れている)。ビルドは不要 |
| `manifest.webmanifest` | PWA の設定(名前、アイコン、全画面で開く) |
| `sw.js` | Service Worker。オフライン用のキャッシュ |
| `icons/` | アプリのアイコン(192px、512px、マスク用512px、apple-touch-icon 180px、favicon 32px) |
| `.gitattributes` | 改行を LF に揃える |

外部から読み込むのは Google Fonts(Zen Kaku Gothic New、Dela Gothic One、IBM Plex Mono)だけ。

## 紙のデータの持ち方

### 座標

- 紙の座標(ローカル座標):広げた紙の左上を原点にした px 単位の座標。紙の大きさは `paper.W × paper.H`
- ワールド座標:作業台の上の座標。折ったあとの各部分は、ローカル座標をアフィン変換で動かした位置にある
- 画面座標:ワールド座標を `view`(拡大率 `s` と中心 `cx, cy`)で画面に写したもの

アフィン変換は `[a, b, c, d, e, f]` の6つの数で表す(`x' = a x + c y + e`、`y' = b x + d y + f`)。

### 画像

- `src.front` / `src.back` には、長い辺を1600pxに縮めたキャンバスを持つ。読み込んだ元の画像(スマホの写真だと展開後に数十MB)は、縮めたら捨てる
- `paper.front` / `paper.back` は、`src` を回転・伸縮して紙の大きさに合わせたもの。回転も伸縮もいらないときは `src` のキャンバスをそのまま使う
- パネルの枠のサムネイルは、長い辺480pxに縮めた data URL(`thumbOf`)
- 画像を変える操作は全部 `setImages` を通る。紙の大きさが変わらなければ `facets` と履歴を残し、変わるときは確認してからリセットする
- 画像の読み込みはアニメーションの途中で終わることがある。アニメーションは終わるときに `facets` を書き戻すので、`whenIdle` で終わるまで待ってから差し替える

### 面(facet)

折った紙は、重なり順に並んだ面の配列 `facets` で表す。配列の後ろほど上(手前)に描く。

```js
{ poly: [[x, y], ...],  // 面の形(ローカル座標の凸多角形)
  M: [a, b, c, d, e, f], // ローカル → ワールドの変換
  flip: false }          // true なら裏が見えている
```

広げた紙は、紙全体の四角形で `M` が恒等変換の面1つ。

### 折る処理

1. 折り線で全部の面を分ける(`splitAll`)。各面の頂点が線のどちら側かで、多角形を2つに切る
2. 動かす側の面に、折り線での鏡映(反射)を掛け、`flip` を反転し、重なり順を逆にする(`finishFold`)。鏡映は「線の法線方向に2倍押しつぶす」変換(`squash(p, n, 2)`)で作る
3. 谷折りなら動かした面を上に、山折りなら下に積む

アニメーションは、押しつぶす量を0から2まで変えて、紙が線の上でめくれていく様子を平面のまま見せる(`foldItems`)。半分を過ぎたところで、表裏と重なり順を切り替える。

### 裏返し・回転と履歴

- 紙全体の裏返しと回転は、行列 `G` に積み上げる
- 履歴(`hist`、`redo`)には、`G` を取り除いた状態の面と、その状態から次の状態への折り方(折り線・動かす側の点・谷/山)を保存する
- 戻す・進むでは、保存した状態に、いまの `G` を掛け直して表示する。こうすると、裏返したあとに戻しても向きはそのまま、折りだけが戻る
- 裏返した状態(`G` の行列式が負)では、谷折りと山折りが入れ替わるので、保存するときと再生するときに入れ替える
- 谷折り・山折りの折り直し(`refold`)は、履歴の最後の項目の折り方(`fold.mode`)だけを書き換え、その前の状態(`base`)から折り直す。手順は増えず、戻す・進むでは書き換えた折り方が再生される。折り直せるかどうかは `refoldable` で持ち、`setMode` で次の操作が始まると消える

## 保存と復元

- IndexedDB のデータベース `origami`、ストア `state` に、キー `current` で1件だけ持つ
- 中身:`v`(形式の版、いまは1)、`t`(保存した時刻)、`front` / `back`(縮めた画像の PNG の Blob)、`rot`、`backMode`、`foldMode`、`opt`、`G`、`facets`(表示している状態)、`hist`、`redo`
- `scheduleSave()` が0.2秒待ってから `saveNow()` を呼ぶ。`updateUI()`(折る・戻す・アニメーションの終わりなど)、`setImages()`、設定の変更から呼んでいる。アニメーション中は `facets` と `G` が食い違うので、終わるまで待つ
- 画像の PNG 化は重いので、キャンバスごとに1回だけ作って `pngs`(WeakMap)に取っておく。復元した画像は、読み込んだ Blob をそのまま使う
- 開いたときは、まずサンプルの紙を出してから `restore()` で非同期に戻す。復元が終わるまで(`saveReady` が false の間)は保存しない。こうしないと、起動時のサンプルの紙で保存が上書きされる
- `t` が `SAVE_TTL`(12時間)より古い保存は読まない。`t` がない保存も同じ
- 形式を変えたら `SAVE_V` を上げる。版が違う保存は読まずに捨てる(次の保存で上書きされる)

## 重なりを見る

- `peekAt` が見ている場所(ワールド座標)。`renderPeek()` が、`facets` を上から順に見て、その点を含む面(`inPoly`)を集める
- 1枚ごとに小さなキャンバスを作り、その面だけを、見ている場所を中心に描く(面の `M` に、ワールド → 小さな絵の変換を掛ける)
- 紙の形が変わる処理(`animate`、`jumpTo`、`resetFolds`)と道具の切り替えで `clearPeek()` を呼んで閉じる。絵柄だけが変わったとき(同じ大きさの画像の差し替え、裏の撮り方の変更)は描き直す

## 描画

- `<canvas>` 1枚に 2D で描く。`draw()` は requestAnimationFrame でまとめて1回だけ `render()` を呼ぶ
- `drawScene(view)` が、マット、面、折り線、プレビュー、スナップの丸を描く。拡大鏡は、同じ `drawScene` を拡大した `view` で円の中に描き直している
- 各面は、多角形で切り抜いた中に、表(または反転した裏)の画像を `M` で変形して描く
- マットの色などは CSS 変数から読むので、ライト・ダークの切り替えに追従する

## 表示範囲の自動調整

`targetView()` が、全部の面の外接矩形を、上の道具と説明文(`#top`)と下のボタン列(`#bar`)の間に収まるように拡大率と中心を決める。上下の余白は、それらの要素の実際の位置を測って決めるので、画面の配置が変わっても追従する。

手で拡大・移動したとき(`userView = true`)は、画面サイズが変わっても `view` を保つ。

## 操作の処理

Pointer Events でマウスとタッチを同じように扱う。キャンバスには `touch-action: none` を付け、ブラウザ自体のスクロールや拡大を止めている。

状態(`mode`)は3つ。

| mode | 状態 |
|---|---|
| `idle` | 何もしていない |
| `drawing` | ドラッグ中(線を引いている、点や辺を合わせている) |
| `pending` | 折り線が決まり、折る側を選ぶのを待っている |

- タッチは指ごとに位置を `touches` に持つ。2本目が触れたら拡大モード(`pinch`)に入り、1本目の操作は取り消す。指が1本以下になったら抜ける
- 辺を合わせるで辺の近くから始めなかったときは、すぐにはメッセージを出さず、指を離したときに出す。2本指の拡大を始めようとしただけのときに、メッセージが出ないようにするため
- マウスでの移動(`mpan`)は、中ボタンか、Space を押している間(`spaceHeld`)の左ボタンで始まる。`mode` には触れないので、線を引いた途中でも使える。ウィンドウからフォーカスが外れたら `spaceHeld` を戻す
- ホイールは、トラックパッドなら移動、マウスなら拡大にする。トラックパッドは、`wheelDeltaY` がちょうど `deltaY` の -3倍になることで見分ける(Chrome/Safari)。ピンチは `ctrlKey` 付きのホイールとして届く
- 折り線の角度の吸い付き(`angleSnap`)は、画面の上の角度で判定する。動かしている端の先は、角や中点への吸い付き(`snap`)を先に試し、吸い付かなかったときだけ角度に揃える(Shift のときは常に揃える)。`snapEnd` がこの順番をまとめている

## 画面の配置(CSS)

- パソコン:グリッドで作業台とパネルを横に並べる
- スマホ(幅820px以下か高さ520px以下):ページ全体のスクロールを止め、作業台を画面いっぱいにする。パネルは `position: fixed` のシートにして、`transform` で出し入れする。閉じているときは `visibility: hidden` にして、フォーカスが入らないようにする
- iPhone の画面端(ノッチやホームバー)は `env(safe-area-inset-*)` で避ける
- マウス向けとタッチ向けで文言を変えるところは、`.fine` と `.coarse` を `@media (pointer: coarse)` で出し分ける

## PWA

### manifest

`display: standalone` で、アドレスバーなしで開く。`start_url` と `scope` は `./` にして、GitHub Pages のサブパス(`/origami-simulator/`)でも動くようにしている。

### Service Worker(`sw.js`)

| 対象 | 方針 |
|---|---|
| ページ本体(画面遷移) | ネット優先。5秒で応答がなければキャッシュを返す。更新がすぐ反映されるようにするため |
| 同じサイトのほかのファイル(アイコン、manifest) | キャッシュ優先 |
| Google Fonts | キャッシュをすぐ返し、裏で更新する |

インストール時に、ページ本体とアイコンを先にキャッシュする。アイコンや先にキャッシュするファイルを変えたときは、`VERSION` を上げると古いキャッシュが消える。ページ本体だけの変更なら上げなくてよい。

`file://` で開いたときは、Service Worker を登録しない。

## 確認方法

自動テストはない。変更したら、ローカルでサーバーを立てて確認する。

```sh
python -m http.server 8000
# http://localhost:8000/ を開く
```

Service Worker は `localhost` か https でしか動かないので、`file://` で開くと PWA の確認はできない。

スマホの画面サイズでは、次のように確認してきた。

- Chrome の開発者ツール(または CDP)で、スマホの画面サイズとタッチを再現する
- Playwright の WebKit で、iPhone の画面サイズを再現する(Safari と同じエンジン。iOS の Safari そのものではない)
- 確認する画面サイズ:幅 320 / 360 / 375 / 390 / 412 / 430px の縦向き、iPhone と Pixel の横向き、パソコン(1280×800)

iPhone の実機ではまだ確認していない。
